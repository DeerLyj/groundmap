# GroundMap 启动命令说明

本文说明如何启动 GroundMap Web 管理台和可选的查询工作台（`debug-console`）。

## 本机 AI-OS-data 快速启动

适用于当前目录布局：`groundmap/` 与 `AI-OS-data/` 位于同一个上级目录，目标 workspace 为 `personal-ai-os`。

在 `groundmap` 仓库根目录打开 PowerShell，直接复制执行：

```powershell
$env:KB_ROOT = (Resolve-Path '..\AI-OS-data').Path
$env:KB_WORKSPACE = "personal-ai-os"
Set-Location .\web
npm run dev:all
```

该相对路径在当前电脑上会解析到 `E:\AI-OS-data`。启动成功后访问：

- Web 管理台：<http://localhost:3006>
- 查询工作台：<http://localhost:3100>

只需要 Web 管理台时，将最后一行改为 `npm run dev`。在终端按 `Ctrl+C` 停止服务。

## 服务说明

| 服务 | 目录 | 默认地址 | 用途 |
|---|---|---|---|
| Web 管理台 | `web/` | <http://localhost:3006> | 浏览与编辑 Wiki、查看图谱、健康度、项目和冲突 |
| 查询工作台 | `tools/debug-console/` | <http://localhost:3100> | 使用本地 Agent 或已配置的模型查询知识库，并查看工具调用过程 |

查询工作台通过 Web 管理台的 `/api/agent-tool` 接口访问知识库，因此单独启动查询工作台前，应先确保 Web 管理台已经运行。

## 环境要求

- Node.js 20 或更高版本；
- Python 3.10 或更高版本；
- npm；
- 可选：GNU Make，用于执行 `make web` 或 `make dev`。

在 GroundMap 仓库根目录检查版本：

```powershell
node --version
npm --version
python --version
```

## 首次安装

在 GroundMap 仓库根目录执行：

```powershell
npm --prefix web install
npm --prefix tools/debug-console install
```

如果需要在查询工作台使用在线模型，复制环境变量模板：

```powershell
Copy-Item tools\debug-console\.env.example tools\debug-console\.env
```

然后在 `tools/debug-console/.env` 中按需填写模型配置。不要把 API key 写进代码、Markdown 或 Git；未配置的模型会在界面中不可用。

查询工作台常用变量：

| 变量 | 说明 |
|---|---|
| `KB_API_BASE` | Web 管理台地址，默认 `http://localhost:3006` |
| `OPENAI_API_KEY` | OpenAI API key，按需配置 |
| `ANTHROPIC_API_KEY` | Anthropic API key，按需配置 |
| `DEEPSEEK_API_KEY` | DeepSeek API key，按需配置 |
| `OPENAI_BASE_URL` | 可选的 OpenAI 兼容 API 地址 |
| `CODEX_BIN` | Codex CLI 可执行文件名或路径 |
| `CLAUDE_CODE_BIN` | Claude Code CLI 可执行文件名或路径 |

## 推荐方式：同时启动 Web 和查询工作台

### Windows PowerShell

```powershell
Set-Location <ENGINE_ROOT>\web
$env:KB_ROOT = "<DATA_ROOT>"
$env:KB_WORKSPACE = "<WORKSPACE>"
npm run dev:all
```

示例中的占位符含义：

- `<ENGINE_ROOT>`：GroundMap 引擎仓库根目录；
- `<DATA_ROOT>`：包含 `workspaces/` 的数据仓根目录；
- `<WORKSPACE>`：`workspaces/` 下要打开的具体工作区名称。

`KB_ROOT` 必须指向包含 `workspaces/` 的目录，不能直接指向某个具体 workspace。

启动成功后访问：

- Web 管理台：<http://localhost:3006>
- 查询工作台：<http://localhost:3100>

两个服务由同一个命令管理，在终端按 `Ctrl+C` 可同时停止。

### macOS / Linux

```bash
cd <ENGINE_ROOT>/web
KB_ROOT=<DATA_ROOT> KB_WORKSPACE=<WORKSPACE> npm run dev:all
```

### 使用 Make

如果系统已安装 GNU Make，也可以从仓库根目录启动：

```powershell
$env:KB_ROOT = "<DATA_ROOT>"
$env:KB_WORKSPACE = "<WORKSPACE>"
make dev
```

`make dev` 同样会启动 `3006` 和 `3100` 两个服务，并为本地回环地址设置代理绕过规则。

## 仅启动 Web 管理台

### Windows PowerShell

```powershell
Set-Location <ENGINE_ROOT>\web
$env:KB_ROOT = "<DATA_ROOT>"
$env:KB_WORKSPACE = "<WORKSPACE>"
npm run dev
```

访问 <http://localhost:3006>。

如果只使用仓库内置的公开示例 workspace，可以省略 `KB_ROOT`；私人或生产数据推荐始终使用独立数据仓。

如果系统已安装 GNU Make，也可以在仓库根目录执行：

```powershell
make web
```

## 分别启动两个服务

需要单独观察日志或分别重启时，可以使用两个终端。

终端 1——启动 Web 管理台：

```powershell
Set-Location <ENGINE_ROOT>\web
$env:KB_ROOT = "<DATA_ROOT>"
$env:KB_WORKSPACE = "<WORKSPACE>"
npm run dev
```

终端 2——启动查询工作台：

```powershell
Set-Location <ENGINE_ROOT>\tools\debug-console
npm run dev
```

查询工作台服务端不会携带 Web 浏览器中的 workspace cookie。它查询的 workspace 由 Web 管理台启动时的 `KB_WORKSPACE` 决定；仅在 Web 页面顶部切换 workspace，不会改变查询工作台所使用的 workspace。

## 生产模式启动

生产模式应先停止正在运行的开发服务器，因为 `next dev` 和 `next build` 共用 `.next/` 目录。

Web 管理台：

```powershell
Set-Location <ENGINE_ROOT>\web
$env:KB_ROOT = "<DATA_ROOT>"
$env:KB_WORKSPACE = "<WORKSPACE>"
npm run build
npm run start
```

查询工作台：

```powershell
Set-Location <ENGINE_ROOT>\tools\debug-console
npm run build
npm run start
```

## 启动后检查

在浏览器打开两个地址，或在 PowerShell 中检查端口：

```powershell
Test-NetConnection localhost -Port 3006
Test-NetConnection localhost -Port 3100
```

检查知识库数据根和 workspace 是否正确：

```powershell
Set-Location <ENGINE_ROOT>
$env:KB_ROOT = "<DATA_ROOT>"
python scripts\k.py --workspace <WORKSPACE> health --json
```

## 常见问题

### Web 管理台能打开，但没有看到目标 workspace

确认：

1. `KB_ROOT` 指向包含 `workspaces/` 的数据仓根目录；
2. `<DATA_ROOT>/workspaces/<WORKSPACE>/` 确实存在；
3. `KB_WORKSPACE` 与目录名完全一致；
4. 修改环境变量后已经重启 Web 服务。

### 点击“查询工作台”后连接失败

确认查询工作台已在 `3100` 端口启动，并检查 `tools/debug-console/.env` 中的 `KB_API_BASE` 是否仍指向正确的 Web 管理台地址。

### 查询工作台可以打开，但模型不可选

在线模型需要在 `tools/debug-console/.env` 中配置对应 API key。本地 Codex 或 Claude Code 需要其 CLI 已安装并可通过 `CODEX_BIN` 或 `CLAUDE_CODE_BIN` 调用。

### 本地请求被代理或 VPN 干扰

优先使用 `make dev`。手动启动时，可确保 `localhost`、`127.0.0.1` 和 `::1` 不经过系统代理。

### 端口已被占用

先停止占用 `3006` 或 `3100` 的旧进程。临时更换端口时，还需要同步更新查询工作台的 `KB_API_BASE` 和 Web 管理台中的查询工作台地址，避免两个服务指向旧端口。
